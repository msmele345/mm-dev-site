# 05 — Deliver the reusable project-update guide and verify complete maintenance flows

Status: ready-for-agent (start when blockers are complete)

[Featured Project Update spec](../../docs/featured-project-update-spec.md)

## What to build

Give the owner a practical template for future add, remove,
replace, and reorder updates, and verify those instructions against the completed
maintenance capability using isolated configurations.

## Acceptance criteria

- [ ] The guide distinguishes authored catalogue, featured selection, published case studies, and presentation registration.
- [ ] It contains a reusable content outline, artwork/readiness checklist, and separate steps for each supported maintenance operation.
- [ ] It explains retention of outgoing published URLs and warns against reusing public slugs for different projects.
- [ ] It explains that draft review and publication are separate and that optional enrichment does not determine readiness.
- [ ] It keeps Project wall curation independent from Current Transmission and the more-projects rail.
- [ ] A maintainer can follow the guide to add a synthetic project, reorder it, replace/unfeature it, rebuild, and still visit its published case study.
- [ ] Representative desktop/tablet/phone composition and keyboard/touch/reduced-motion behavior are visually and behaviorally verified.
- [ ] Fixed-four explanatory documentation is updated where necessary while historical decisions remain intact.
- [ ] Required repository checks pass and verification evidence is recorded; owner review items are checked only after review occurs.
