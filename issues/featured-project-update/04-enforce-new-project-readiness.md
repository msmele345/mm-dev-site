## What to build

Provide a dependable onboarding path for a future bespoke project:
complete curated content and registered art produce a working tile and case study,
while incomplete or contradictory local configuration stops the build clearly.

## Acceptance criteria

- [ ] A synthetic new identity with distinct tile and case-study presentation can be authored, published, and featured through the documented extension points.
- [ ] Its title, pitch, narrative, stack, theme, reviewable images, image descriptions/captions, and destination render correctly through the public pages.
- [ ] Local image references resolve; labeled draft plates and draft copy keep the established review behavior.
- [ ] A new identity requires no new project-specific dispatch branch in shared wall or case-study shells.
- [ ] Missing/blank required content, duplicate catalogue slugs, invalid routes/URLs, unresolved assets, and missing registration fail with slug/field-specific errors.
- [ ] Invalid production-shaped fixtures demonstrate actual build failure, beyond isolated validator assertions.
- [ ] Missing repository/demo links and failed GitHub enrichment still render complete curated content.
- [ ] The synthetic tile verifies keyboard/touch access, deliberate reduced-motion art, and the shared animation contract.
- [ ] No actual new project is added to the production lineup.
