## What to build

Preserve the current four tiles and case studies through explicit
presentation registrations, making future project identities registerable without
adding dispatch branches to the shared wall or case-study shell.

## Acceptance criteria

- [ ] All four current tiles retain their order, art, palette, typography, and case-study links.
- [ ] Published case studies retain their current artwork and curated narrative.
- [ ] A cohesive registration point associates each project with its tile and appropriate case-study artwork.
- [ ] Shared wall and case-study shells no longer assume that an unknown project should render nothing or inherit unrelated groovebox artwork.
- [ ] Registration checks name missing or conflicting project presentation references.
- [ ] Existing static, ambient, crescendo, off-screen pause, keyboard, and touch behavior remains verified through rendered pages.
- [ ] Required checks pass and the production four-project lineup remains unchanged.

## Blocked by

None — can start immediately.
